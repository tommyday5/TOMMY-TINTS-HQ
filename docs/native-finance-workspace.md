# Native finance workspace — 22 November 2026

The owner-only /hq/finance interface now uses persisted HQ inputs rather than requiring spreadsheet editing. /hq/finance/sheets retains the existing read-only workbook reference and /api/hq/finance remains unchanged.

Overview combines estimated balance after recorded commitments, target cards and upcoming bill timeline. Edit Finances supports owner-reported balance with date, target and named dated bills. Transactions & reconciliation supports signed manual entries, category correction and classification review, with stale-revision protection and a filter for entries needing review. Entries have client-generated stable IDs: replay cannot duplicate a saved transaction. Values are integer pence; unknown balance/target remain null. Transfers/loans/drawings are distinct categories. Review NEVER verifies a bank receipt, marks a job paid or updates provider/Sheets balances.

All records persist in additive finance_* tables in customer_requests.sqlite3 on /data. Changes and audit revision metadata commit together. Owner-only APIs require CSRF, bounded payloads and no-store. No provider or payment calls occur. Customer accounts cannot access these routes. Sheets/source histories are retained separately; no import, merge or production financial adjustments are performed by deployment.

Limitations: no bank ingestion, invoice allocation, payment-evidence matching, automated reconciliation, recurring bill generation, bill paid/void workflow, deletions or financial time-series charts. Transaction display is limited to the latest 200, with total shown. The reconciliation tab is an entry/classification review workflow, not completed bank reconciliation. All known bill dates remain editable. Forecast is a dated owner balance minus recorded bills due through 30 days, including overdue; it excludes unrecorded expenses and future receipts. There is no bank-derived freshness guarantee. Targets are planning inputs, not received revenue. No mockup figures are included in production. Further finance input types need separate implementation.

## Existing source continuity correction

The new overview now calls the unchanged owner-only /api/hq/finance endpoint on entry, manual refresh and return to foreground. This restores the original mapped spreadsheet metrics, review count, data-through date, last-refresh time, source-cell labels, missing-data notes and stale warnings within the new workspace. It does not migrate/copy values into HQ inputs or sum source figures with manual records. Failed reads hide old source figures and preserve local entries. Backgrounding clears source figures; an in-flight background response does not repopulate them. Links expose existing payment evidence, Integration Health and jobs/costing workflows.

An empty HQ bill register is unknown, not proof of zero commitments: the native available-after-commitments figure remains unavailable until both a balance and at least one bill record exist. Completeness of manually entered bills still requires owner review. Live source access depends on existing persistent owner consent and workbook permissions; production grant contents were not accessed. Monzo/DNA ingestion and automatic invoice/bank matching remain unconnected. This correction restores source visibility, not end-to-end financial reconciliation.
